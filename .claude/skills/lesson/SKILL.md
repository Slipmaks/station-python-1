# Урок для «Станції Пітон-1»

Запит користувача: $ARGUMENTS

Виконуй кроки по черзі, нічого не пропускай і не вгадуй: на кожне «як?» відповідь є тут або в `src/lib/lessons/intro.ts`.
Не комить і не пуш — git веде користувач. Нічого не питай, доки не дійдеш до звіту, якщо інструкція прямо не каже запитати.

## Що треба знати про гру

- Учні 9 класу відновлюють космічну станцію «Пітон-1». **Урок** — окрема станція (сторінка `/l/<id уроку>`),
  **відсік** (mission) — одне завдання (сторінка `/m/<id відсіку>`). Відсіки відкриваються по черзі, за кожен — 1–3 зірки,
  за весь урок — сертифікат.
- Увесь текст для учнів — **українською**: звертання на «ти», короткі речення, апостроф `’`, лапки «», тире —.
- Python у грі виконує **власний навчальний інтерпретатор** сайту (`src/lib/py.js`), а не справжній Python. Він уміє не все (крок 2).
- Уроки — це TypeScript-файли, міграції БД для них не потрібні. Після `git push` урок з’являється на сайті,
  і вчитель відкриває його класу в кабінеті.

| Файл | Що там |
|---|---|
| `src/lib/types.ts` | формат уроку й відсіку з коментарями — **прочитай повністю** |
| `src/lib/lessons/intro.ts` | урок 1 — **зразок кожного виду відсіку**, прочитай повністю, перш ніж писати |
| `src/lib/lessons/index.ts` | `LESSONS` — уроки по порядку (номер уроку = місце в списку) |
| `src/lib/checks.ts` | помічники для перевірок коду: `count`, `outIs`, `lastLine`, `stripStrings` |
| `src/lib/lessons/lessons.spec.ts` | автоматичні перевірки вмісту всіх уроків (`npm test`) |
| `e2e/content.spec.ts` | проходить кожен відсік кожного уроку в браузері |

Готові зразки в `intro.ts`: `radio` — проста задача з кодом; `airlock`, `engine` — задачі з `input()` і `tests`;
`repair` — ремонтний відсік (`steps`); `archive` — вікторина з запитаннями; `decoder` — вікторина «Що виведе програма?»;
`scanner` — сканер типів.

## Крок 2. Перевір, що вміє інтерпретатор

Кожен шматок коду — розв’язок, стартовий код, код у вікторині, приклад для пісочниці — спершу запусти інтерпретатором сайту:

```sh
node scripts/py.ts <файл.py> [введення1 введення2 …]   # введення — по одному на кожен input()
echo "print([1, 2] * 2)" | node scripts/py.ts
```

Тимчасові `.py` клади в тимчасову теку — scratchpad із системних інструкцій, а якщо його немає, `/tmp`, — але не в репозиторій.

**Працює** (перевірено):
- `print(…, sep=…, end=…)`, `input()`, `int()`, `float()`, `str()`, f-рядки (і `{x:.2f}`), `round()`, `abs()`, `import math`;
- `if`/`elif`/`else`, `and`/`or`/`not`, `while`, `for … in range(a, b, крок)`, `for x in список`, `break`, `continue`, `pass`;
- рядки: індекси, зрізи, `len`, `in`, `+`, `*`, `ord`, `chr`, порівняння, методи
  `upper lower title capitalize strip replace split count find startswith endswith isdigit isalpha join` — **лише в найпростішій формі**:
  `strip()` без аргументу, `replace(a, b)` без третього, `find(x)` і `count(x)` без меж, `split()` / `split(sep)` без другого,
  `startswith`/`endswith` з одним рядком. Інші форми інтерпретатор **мовчки** виконує не так, як Python, і тести цього не помітять;
- списки: `[1, 2]`, `[]`, `list(range(…))`, `list('abc')`, `[0] * n`, `a + b`, індекси (і від’ємні), зрізи з кроком (`a[::-1]`),
  `a[i] = x`, `a += [x]`, копія `a[:]`, вкладені списки `m[i][j]`, обмін `a[i], a[j] = a[j], a[i]`;
- методи списків: `append insert pop remove index count sort reverse clear`, і `a.sort(reverse=True)`;
- `len sum min max sorted` (і `sorted(a, reverse=True)`), `in` / `not in`, `input().split()`, `' '.join(список_рядків)`, `==` для списків;
- уведення й виведення списку: `list(map(int, input().split()))`, `list(map(float, …))`, `print(*a)`, `print('Площі:', *a, sep=…)`.

**Не працює** — не використовуй ні в розв’язках, ні в підказках, ні у вікторинах:
- генератори списків `[x * 2 for x in a]` і `' '.join(str(x) for x in a)`;
- `enumerate`, `zip`, `filter`, `any`, `all`, `lambda`, `key=` у `sort`/`sorted`/`min`/`max`, `a.index(x, start)`;
- методи рядків `lstrip rstrip swapcase rfind index isalnum isspace isupper islower isnumeric center ljust rjust zfill partition splitlines format`,
  форматування `%`, ширина й вирівнювання у f-рядках (`{x:5}`, `{x:>5}`, `{x:6.2f}`) — працює лише `{x:.2f}`;
- `del`, `a.extend()`, `a.copy()`, присвоєння зрізу `a[1:3] = …`;
- `from … import …`, `random` і будь-які модулі, крім `math`;
- `def`, `class`, `try`, словники й множини `{…}`.

`' '.join(a)` працює лише для списку рядків; числа через пропуск виводить `print(*a)`.

Якщо без якоїсь конструкції тему не викласти, **не вигадуй обхідних шляхів і не змінюй `py.js`**. Збудуй урок без неї,
а у звіті напиши: «Для теми потрібне розширення інтерпретатора: …».

## Крок 4. Напиши файл уроку

**Новий файл чи заготовка?** Якщо в `LESSONS` є урок з `missions: []` на цю тему (зараз це `lists.ts` — «Списки»),
заповни його: `id` і назву файлу не змінюй, `title` можна уточнити. Інакше — новий файл `src/lib/lessons/<id>.ts` (id уроку — за правилами id вище)
і рядок у `LESSONS` в `index.ts`, у кінці списку. Уроків — не більше 10. `title` — до 40 знаків (учні бачать «Урок 2. <title>»).

Оформлення — як в `intro.ts` (відступ — 2 пробіли, коми в кінці). Імпортуй лише помічники, які справді використав.

```ts
import { count, lastLine, outIs, stripStrings } from '../checks.js';
import type { Lesson, Mission } from '../types.js';

/* Урок 2: <тема>. Відсіки відкриваються в порядку цього масиву. */
const missions: Mission[] = [
  { id: '…', name: '…', topic: '…', slide: '…', kind: 'code', story: '…', task: '…', expected: '…', starter: '',
    checks: [ /* … */ ], hints: ['…', '…'], solution: '…', wrong: ['…', '…'], learned: '…' },
  // …
];

const examples: [string, string][] = [
  ['Назва прикладу', "код\n"],
];

const lesson: Lesson = {
  id: '…',
  title: '…',
  missions,
  examples,
  certificate: {
    ranks: [
      { from: 0.9, title: '…' },
      { from: 0.67, title: '…' },
      { from: 0, title: '…' },
    ],
    summary: 'Що учні вміють після уроку — одне речення.',
    next: 'Про що наступний урок — одне речення.',
  },
};
export default lesson;
```

### Спільні поля відсіку

- `id`, `name` — див. крок 3. `topic` — поняття коротко: «Списки: append()». `slide` — лише з презентацією.
- `story` — сюжет відсіку. `learned` — одне речення «що ти вмієш тепер», його показують після проходження.
- Розмітка в `story`, `task`, `hints`, `inputsNote`, а також у `task` і `hint` кроків — **лише** `<b>`, `<i>`, `<code>`, `<br>`,
  кожен тег закрито. Знак `<` у цих текстах пиши як `&lt;`. В `q`, `options`, `explain` і `learned` — звичайний текст без тегів.

### Задача з кодом — `kind: 'code'`

- `task` — що зробити. Конкретний рядок, який треба вивести, — у `<b>…</b>`.
- `expected` — **точно** те, що виводить `solution`: запусти `solution` через `scripts/py.ts` і скопіюй вивід.
  Для програми з `input()` — масив діалогу, розрізаний у місцях введення (як в `airlock`):
  `[['Як тебе звати? ', 'out'], ['Марко', 'in'], ['\nПривіт, Марко', 'out']]`.
- `starter` — `''` або програма з помилкою для задач «знайди й виправ». Стартовий код **не має** проходити перевірки.
- `checks` — 2–3 перевірки: що використано конструкцію теми, і що результат правильний (рецепти нижче). `label` — що саме перевірено.
- `hints` — рівно дві. Перша підштовхує (яку конструкцію взяти й навіщо), друга — майже розв’язок у `<code>…</code>`.
  Перехід на новий рядок у підказці — `\n` усередині `<code>`, як у `lights`.
- `solution` — найпростіший розв’язок тим, що вже вивчено. Відступ у циклах — 4 пробіли.
- `wrong` — 1–3 **неправильні** програми, які перевірки мусять відкинути (тест це перевіряє, див. `wrong` в `intro.ts`):
  вписана готова відповідь (`print('75')`, `print([5, 12, 7])` після правильно складеного списку, готовий текст у `print`
  усередині циклу-пустушки `for i in range(1):`), розв’язок без конструкції, якої вчить відсік (без циклу, без `append`,
  без списку в змінній), типова помилка учня. Вимога — для **всіх** задач з кодом, і для давніших відсіків теж: тест перевіряє всі.
  Кожну спершу запусти через `scripts/py.ts`: вона має працювати без помилки, інакше її відкине вже «без помилок» і вона нічого не перевіряє.
  Якщо тест каже, що програма з `wrong` проходить, — посиль `checks`, а не прибирай програму з `wrong`.
- Програма з `input()` — ще три поля, як в `airlock`:
  - `tests: [{ inputs: ['…'] }, { inputs: ['…'] }, { inputs: ['…'] }]` — три різні набори введення, по одному значенню
    на кожен `input()`; перший набір — той, що в `expected`;
  - `inputsNote` — що отримає програма під час перевірки;
  - `otherDataLabel` — підпис перевірки на інших даних: «Працює й для інших списків».

**Рецепти перевірок** (`c.src` — код учня, `c.out` — вивід, `c.inputs` — введення поточного тесту, `c.res.error` — помилка):

| Що перевірити | `fn` |
|---|---|
| викликано функцію чи метод хоча б раз (рахує й `a.append(…)`) | `c => count(c.src, 'append') >= 1` |
| рівно / не більше N разів | `c => count(c.src, 'print') === 1` · `c => count(c.src, 'print') <= 2` |
| є оператор чи слово поза рядками й коментарями | `c => stripStrings(c.src).includes('//')` · `c => /\bfor\b/.test(stripStrings(c.src))` |
| у коді немає готової відповіді — саме `c.src`, **не** `stripStrings`, інакше пройде `print('75')` | `c => !c.src.includes('86400')` |
| функцію не використано (задача саме про цикл, а не про `sum()`) | `c => count(c.src, 'sum') === 0` |
| текст записано в коді лише раз (повторює цикл) | `c => c.src.split('Сигнал!').length === 2` |
| виводиться змінна, а не готове значення (`print(warm)`, а не `print([5, 12, 7])`) | `c => /\bprint\(\s*warm\s*\)/.test(stripStrings(c.src))` |
| програма працює без помилок | `c => !c.res.error` |
| точний вивід (задача без `input()`) | `{ label: 'Виведено …', fn: outIs('…'), diff: '…' }` — той самий текст, що в `expected` |
| останній рядок виводу | `c => lastLine(c) === '…'` |
| задача з `input()` — очікуване рахуй з `c.inputs` | `c => lastLine(c) === String(Math.max(...c.inputs[0].split(' ').map(Number)))` |

- У задачі з `tests` **кожна** перевірка виконується на **кожному** наборі введення. Тому `outIs('…')` з готовим текстом там не підходить:
  очікуване рахуй з `c.inputs`, як в `engine`. `diff` у таких задачах не пиши.
- Щоб відповідь не можна було просто вписати: у задачі без `input()` додай перевірку конструкції теми
  або «у коді немає готової відповіді» (як у `power`); у задачі з `input()` це ловлять самі `tests`.
- Значення змінних через `c.res.env` не перевіряй — перевіряй вивід.

### Ремонтний відсік — `kind: 'code'` зі `steps`

Замість `task`/`expected`/`starter`/`checks`/`hints`/`solution` — `steps`: 3–5 програм, як в `repair`.
Кожна має `task`, `expected` (= вивід `solution`), `starter` з **однією** типовою помилкою теми
(забута дужка, `IndexError`, неправильний метод…), `hint` (одна підказка) і `solution`. Перевірки для кроків будуються самі.

### Вікторина — `kind: 'choice'`

- `items` — 4–6 запитань. У кожного 4 різні `options`, `answer` — номер правильного варіанта з нуля, `explain` — 1–2 речення,
  чому правильно саме так. Неправильні варіанти — типові помилки учнів, а не відверта нісенітниця.
- Запитання з теорії — поле `q`. «Що виведе програма?» — поле `code` (без `q`) і `codeOpts: true`; правильний варіант —
  **точно** вивід цього коду в **один** рядок (тест звіряє з інтерпретатором).

### Сканер типів — `kind: 'types'`

Як `scanner`: `pool` — щонайменше `count` пар `[значення як у коді, 'int' | 'float' | 'str' | 'bool']` без повторів, `pass` ≤ `count`.

### Сертифікат і приклади

- `certificate.ranks` — три звання від найвищого; `from` — частка зібраних зірок: `0.9`, `0.67`, `0`.
  Звання — у космічному дусі, не повторюй звань з `intro.ts`.
- `examples` — 4–8 прикладів для пісочниці `[назва, код]`, що показують поняття уроку. Кожен має запускатися без помилок.

- [ ] Тексти — українською, без русизмів, зрозумілі дев’ятикласнику; немає англійських слів, крім коду.
- [ ] Порядок відсіків — від простого до складного; останній — підсумковий.

## Крок 6. Автоматичні перевірки — по черзі, кожна має бути зеленою

1. `npm test` — вміст уроків. Що робити, коли тест падає:

   | Тест, що впав | Що виправити |
   |---|---|
   | `id уроків і відсіків — малі латинські літери…` | id: лише `a-z`, `0-9`, дефіс, починається з літери |
   | `id … унікальні` / `назви відсіків не повторюються` | інший id чи назва |
   | `є сертифікат; звання — від найвищого…` | `certificate`: три звання, `from` спадає, останнє — `0` |
   | `приклади для пісочниці запускаються без помилок` | запусти приклад через `scripts/py.ts`, виправ |
   | `у текстах лише <b>, <i>, <code>, <br>…` | розмітка: чужі теги прибери, незакриті — закрий, `<` → `&lt;` |
   | `розв’язок проходить, стартовий код — ні` | розв’язок не проходить — помилка в `solution` або в `checks`; стартовий код проходить — посиль перевірку чи зміни `starter` |
   | `«Очікуваний результат» — це вивід еталонного розв’язку` | скопіюй вивід `solution` у `expected` |
   | `перевірка на інших даних має пояснення…` | додай `inputsNote` і `otherDataLabel` |
   | `неправильні програми (wrong) перевірки відкидають` | `wrong` немає — додай; програма з `wrong` проходить — посиль `checks` (рецепти вище) |
   | `правильні відповіді збігаються з виводом Python` | варіанти не повторюються; правильний = точний вивід `code` |
   | `type() збігається з відповідями…` | тип у `pool` неправильний або значення повторюється |

2. `npm run check` — 0 помилок типів. Якщо всі помилки поза `src/lib/lessons/` (наприклад, `Cannot find module './$types'`), це середовище,
   а не урок: запусти `npx svelte-kit sync` і повтори. Не допомогло — вважай крок пройденим, якщо в `src/lib/` помилок немає,
   і напиши про це у звіті.
3. `npx playwright test e2e/content.spec.ts` — кожен відсік у браузері правильними відповідями на ★★★ (кілька секунд на урок).
   Коли падає — відкрий знімок екрана з `test-results/…/test-failed-1.png` інструментом Read і прочитай текст помилки.
4. `npm run test:e2e` — усі тести в браузері (~2 хв).

Не послаблюй і не видаляй тести та перевірки відсіків, щоб стало зелено. Якщо в `npm run test:e2e` падає тест, не пов’язаний
з твоїм уроком: збережи текст помилки, запусти цей тест окремо (`npx playwright test e2e/<файл>.spec.ts:<рядок>`), потім знову весь набір.
Обидва зелені — це випадковий збій: напиши у звіті, який тест і з якою помилкою. Падає знову — зупинись і перешли користувачу текст помилки.

## Крок 7. Звіт користувачу (російською — так спілкується користувач)

- Таблиця відсіків: № · назва · вид · що відпрацьовує · слайд.
- Що з теми чи презентації не ввійшло й чому (зокрема «потрібне розширення інтерпретатора: …»).
- Результати кроку 6: скільки тестів пройшло в кожній команді.
- Що далі: переглянути урок локально (`npm run dev`, увійти вчителем, відкрити урок класу, увійти учнем),
  закомітити й запушити; на сайті вчитель відкриває урок класу кнопкою «Відкрити урок класу» в кабінеті.

## Зміна наявного уроку

- **Ніколи не змінюй `id`** уроку чи відсіку: на них тримається прогрес учнів у БД.
  Назви (`name`, `title`) і тексти змінювати можна.
- Видалити відсік або переставити відсіки в уже опублікованому уроці — спершу запитай користувача:
  зірки учнів за видалений відсік зникнуть із підсумку уроку.
- Учні, які вже пройшли відсік, зберігають свої зірки, навіть коли перевірки змінилися.
- Після змін — кроки 5–7.
